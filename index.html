AI-native SDLC: how the vendors compare

What each vendor recommends for an AI-native software development lifecycle, and where they agree or differ. Anthropic's playbook is used as the baseline; every other vendor is rated against it.

Last updated 2026-10-24 · Vendors reviewed: Anthropic, AWS, Atlassian, OpenAI, Microsoft, GitHub, Google

How to read this. Rows marked "our assessment" are the author's judgement, not vendor claims. Colour shows how a vendor's approach relates to the baseline; the label in each cell says the same in words. Each cell links to the section it is based on.

The short version

Where they agree

  • Plan before codeAll seven

    Every vendor puts a written plan or spec ahead of implementation: intent, spec and plan files (Anthropic), Inception (AWS), versioned specs (Atlassian), a Plan phase (OpenAI), Research and Plan (Microsoft), Plan Mode (GitHub), specs and tests first (Google).

  • Humans keep judgement, agents do the first passAll seven

    Agents plan, build and give first-pass review. People own intent, risk, final review and sign-off.

  • Rules are written down where the agent reads themAll seven

    CLAUDE.md and skills, steering files, AGENTS.md, instruction files. Atlassian does the same through a central context graph rather than repo files. Google adds six context types.

  • Measure the changeFive of seven

    Anthropic, AWS, Atlassian, OpenAI and GitHub all name some way to measure. Depth varies. Microsoft's repo gives no outcome metrics. Google measures the agent (evals, observability), not delivery.

  • Start small, then expandFive of seven

    Anthropic, AWS, Atlassian, OpenAI and Google advise starting with one stage, pilot or well-specified task.

Where they differ

  • How firmly rules are enforced

    Anthropic describes deterministic enforcement (hooks, managed settings) and GitHub an admin control plane. AWS leans on pipeline gates and steering files. The rest say little. Google puts guardrails and hooks in the harness.

  • Team and operating model

    Only AWS prescribes a team model: AI Pods, mob sessions, new vocabulary. Google gives hybrid-team and hiring guidance without a model. Anthropic, OpenAI and GitHub leave team structure open.

  • Closing the loop after release

    Only Anthropic describes an autonomous loop where production signals become the next intent. AWS, Atlassian and Google cover parts of it, with humans in the loop. OpenAI keeps engineers on sign-off. Microsoft and GitHub do not cover it.

  • Where context lives

    Anthropic, AWS, OpenAI, GitHub and Google keep it in repo files. Atlassian builds a permissioned graph across Jira, Confluence and code.

  • Evidence offered

    AWS, Atlassian and OpenAI quote outcomes, all vendor-reported. Google cites outside studies. Anthropic, Microsoft and GitHub give none for delivery results.

  • Scope of the source

    Anthropic and AWS publish methods. OpenAI publishes a guide. Google publishes a conceptual paper (Day 1 of a five-day series). Atlassian skips Test and Deploy. Microsoft is a starter kit and GitHub a product announcement.

Our read (assessment)

  • Anthropic's playbook is the most implementable: strongest on enforceable controls, self-verification and closing the loop.
  • Others add what it lacks: AWS a team model and business case, Atlassian system-of-record context and measure-before-scaling, OpenAI a simple delegate, review, own framing, Google a verification-first test for vibe coding vs production.
  • The vendors agree on principles far more than on mechanics. Differences are mostly in enforcement, operating model and evidence.
